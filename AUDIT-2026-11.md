# Open-source readiness audit -- November 2026

A second pair of eyes before the repositories are made public. Nothing here changes either repository's visibility, which is the
owner's decision alone.

- **Audited:** this repository at `76ea1bd` (branch `main`), and `shepherd-vita-plugin` at `69701f0` (read-only; nothing in it was changed).
- **Machine:** a clean cloud container, Ubuntu 24.04.5 x86-64, 4 cores, 15 GB RAM, git 2.43.0, Python 3.13, CMake 3.28, Ninja,
  Docker, gcc / clang 18. No Mac, no PS Vita, no game files. Its egress proxy refused Microsoft's .NET download host and HTTPS
  downloads from GitHub (git over HTTPS worked), so vitasdk could not be installed. That is a limit of this sandbox, not of the repo.
- **Date:** 2026-11-02.

### Small fixes in this PR (all verified here; carry them upstream by hand)
1. `vita/toolchain/setup-fork.sh` -- `git apply --intent-to-add` replaced by `git apply` plus `git add -N` on the files the patch
   creates. On git 2.43.0 (Ubuntu 24.04's default) `apply --intent-to-add` drops every index entry the patch doesn't touch, so
   the script stopped with "untracked files after applying the patch". I reproduced the bug in a 2-file toy repo. The new
   lines give the intended state (38 modified, 7 new files marked intent-to-add, full index). Negative control: the old
   script still fails on the same tree.
2. `tools/devlog-receiver/test_receiver.py:855` -- the export replaced a LAN address with the documentation address `192.0.2.125`.
   The test asserts that this address is an RFC 1918 LAN address, so it failed on every clean export (41 of 42 tests passed). It
   now uses the generic `192.168.200.7`, and 42 of 42 pass. Upstream, use a generic address here too, so the scrub never needs
   to touch this line.
3. `THIRD-PARTY-NOTICES.md`:
   - adds the C# crunch port (`Crunch.cs`) to "In this repository";
   - adds Box2D patch P3 (applied, and listed in `PATCHES.md`, but missing from the notice row);
   - adds a "Licence texts" section with crunch's zlib notice and dotnet/runtime's MIT notice, both checked byte for byte
     against the upstream files (crunch at the pinned commit `8708900e`, dotnet/runtime at `v8.0.31`).
4. `README.md` "You need" -- now says what is true today: the full build needs a Mac with Apple silicon, Linux builds the C#
   tools, and zsh and Homebrew SDL3 are required. Neither zsh nor SDL3 was listed before.

## 3. Leak scan

Scope: every tracked file and every blob reachable from any of the 26 commits (all authored and committed as
`NOVA <noreply@example.com>`; 138 history-only blobs, all older versions of current files; no file was ever deleted).
No secret values are reproduced here.

### Game-derived content -- clean
- **Decompiled code:** no decompiler fingerprints (ILSpy / dnSpy / dotPeek headers, compiler-generated names) beyond two benign
  hits:
  - `Physics/PhysWorld.Stage2.cs:127` reflects on a backing field by name;
  - `vita/llvm/foreign-gate.sh:89` names a symbol of Shepherd's own code.
- **What is present by design:** reflection lookups of game types by name (e.g. `Icalls/VitaTouch.cs:307,369`), prose about the
  game's internal behaviour (e.g. `Runtime/K10Load.cs:8,13`), and lists of the game's assembly names
  (`vita/gameaot/proto/modules-game.txt`, `vita/gameaot/owner-modules-p.txt`). This is interoperability information, not code.
  The owner should still be comfortable publishing it.
- Hard-wired first-game identity strings at `Icalls/AppIcalls.cs:97-99` (product, company, bundle id). The build GUID at
  `:100` is all zeros. These are listed as "first-game seams" in `docs/PORTING-ANOTHER-GAME.md`.
- **Game assets / large binaries:** none. The only binaries are the 14 placeholder PNGs. The largest file is `docs/ledger/index.html`
  (487 KB of text, no embedded images; it loads Google Fonts).
- **Encryption keys:** none. The FMOD bank key is read from the user's own install at run time and never stored
  (`tools/FmodBake/GameKey.cs`). `tools/VitaPack/KeyScan.cs` scans for key bytes and has no literals. A comment at
  `GameKey.cs:30` names a local, git-ignored `decomp/` folder as the source of a field order (a fact, not code).
- **The repo's own gate:** `derived_leaks.py` is vacuous on any machine but the owner's (no `Derived/` folder), so the owner
  should run it upstream before each export.

### Personal data -- clean
- **E-mail addresses:** none at all in the tree or history.
- **macOS home / volume paths (`/Users`, `/Volumes`):** only the placeholder `YOU` in
  `tools/devlog-receiver/com.shepherd.devlog-receiver.plist:26,49,51` and memory-card mount globs in `vita/tools/push-kit.sh:170`
  and `vita/tools/read-logs.sh:55`.
- **Names, usernames, hostnames, device ids:**
  - no personal names: the only copyright lines are the LICENSE's "The Shepherd project contributors" and upstream authors
    (Box2D, crunch);
  - no owner handle;
  - no Vita IDPS / PSID / account ids;
  - the MAC addresses (`test_receiver.py:446`, `selftest.c:204-224`) and `host.local` (`selftest.c:179`) are synthetic test values.
- **IP addresses:** only documentation ranges (192.0.2.0/24), RFC 1918 network bounds, and synthetic test values.
- **Scrub side effects:**
  1. `test_receiver.py:855` was broken by the address swap (**fixed**).
  2. The plist's command uses `$SHEPHERD_WORK`, but its `EnvironmentVariables` (`plist:28-32`) never sets it. Under launchd
     the receiver root becomes `/devlog`. The README's install step (`tools/devlog-receiver/README.md:155-159`) copies the plist
     as-is and never says to replace `YOU` or set `SHEPHERD_WORK`. Recommendation: add `SHEPHERD_WORK` to the plist's
     `EnvironmentVariables` with a `YOU` placeholder and say so in the README.
- **Owner-specific but not personal:** "main disk is nearly full" (`tools/FmodBake/README.md:27`) and the sparsebundle
  message at `vita/shepherd/build.sh:361`.

### Secrets -- clean
- No GitHub / Anthropic / AWS / Slack / Google token shapes and no private-key blocks, in the tree or history.
- One keyword hit is a false positive: `Shepherd.Assets/AddressablesCatalog.cs:23`, a Unity path token constant.
- Long hex literals are SHA / HMAC / AES test vectors (`vita/runtime/tests/test_crypto.c`, `vita/devlog/mac/selftest.c`), the
  all-zero build GUID, or (in `vita/devlog/mac/test.sh:47`) a synthetic test token.
