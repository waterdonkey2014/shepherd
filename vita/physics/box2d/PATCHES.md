# Changes to vendored Box2D 2.3.1

zlib licence, condition 2: altered source versions must be plainly marked as such. Every file under `Box2D/` that we alter
gets a header comment beginning `ALTERED for Shepherd:` and a row in the first table, with the reason, its runtime switch and its
flag-off proof. The physics plan (v2, `physics-plan-v2.md` section 1.2; the map from its v1 numbering is
`vita/notes/physics-plan-v2-map.md`) changes Box2D's source only through the patches **P1** (trigger phase + kinematic
triggers, Stage 2), **P2** (the speed clamps as globals, only if a probe selects a non-stock clamp -- the Unity editor oracle E1 did:
applied 2026-10-20), **P3** (multicore, incl. the GJK
statistics counters of `Collision/b2Distance.cpp`, Stage 7) and **P4** (the island rule, only if the Unity editor oracle selects
H-KINISLAND=`stop`) -- and **P5** (Unity 2022.3's polygon weld, Stage 4 step 4b: measured on the Unity editor oracle, applied
2026-10-20). Each comes as a separate, clearly marked patch whose flags-off path is stock, proved by T1 (8/8 unchanged).
Everything else the plan needs is a build-level substitution (B1-B3 below: no Box2D file changed) or the Unity layer of ours
(`shim/sp_unity.cpp`, Stage 1: no Box2D file changed -- it uses only Box2D's public API, a `b2ContactFilter` subclass and
`b2Body::SetMassData`).

## Build-level substitutions (no Box2D file changed; behaviour differs from stock)

| # | where | what | reason | switch |
|---|---|---|---|---|
| B1 | `vita/physics/CMakeLists.txt`, `shim/sp_trig_override.h`, `shim/sp_trig.c` | every Box2D translation unit (and our shim, which inlines Box2D headers) is compiled with `-include shim/sp_trig_override.h`, which processes `<math.h>` first and then routes `sinf`/`cosf` to our `sp_sinf`/`sp_cosf` (double-precision Cody-Waite + Taylor, one final rounding) | plan v2 section 1.2 item 4: Apple libm and newlib give different last bits, which breaks Mac == Vita. Measured 2026-10-07: with stock libm, 1/8 T1 scenarios differ on the Mac (Apple libm) and 3/8 on the emulated Cortex-A9 (newlib); with B1, 8/8 match on both (`vita/notes/physics-stage0a.md`) | `-DSHEPPHYS_TRIG_OWN=OFF` builds stock trig |
| B2 | `vita/physics/CMakeLists.txt`, `shim/sp_b2glue.cpp`, `shim/sp_core.cpp` | every build (Mac and Vita) leaves out `Common/b2Settings.cpp` and links `shim/sp_b2glue.cpp`, which defines its four symbols: `b2_version` {2, 3, 1} and `b2Log` (vprintf) exactly as stock, and `b2Alloc` / `b2Free` through libshepphys's **arena** -- the pool's allocator (16-byte granules, segregated LIFO free lists, a bump pointer: deterministic offsets) on its own fixed block that never moves (Box2D keeps raw pointers into its allocations, so it cannot grow by copying like the mirror pool). Before `sp_init`, with `SP_INIT_B2_MALLOC`, or once the arena is full, `b2Alloc` falls back to malloc (stock) and the fallback is counted (`sp_b2_get_stats`) | plan v2 section 1.2 item 5 (Stage 1): no malloc during a step, one fixed budget on the Vita (`SHEPHERD_PHYS_POOL_MB` / the arena, 4 MiB each by default). Proof (2026-10-14, Stage 1): T1 8/8 unchanged on the Mac and QEMU (allocation addresses feed no arithmetic); the dylib's link map has `b2Alloc` / `b2Free` / `b2Log` / `b2_version` from `sp_b2glue.cpp.o` and no `b2Settings.cpp.o` (`build.sh mac` checks it: `out/b2-linkmap.txt`); the S1 self-test ends with 0 live arena blocks; the intro drive's arena high water 125 KiB of 4 MiB, 0 malloc fallbacks | `-DSHEPPHYS_B2=OFF` builds stock `b2Settings.cpp`; at run time `SHEPHERD_PHYS_B2=malloc` (`SP_INIT_B2_MALLOC`) keeps malloc / free |
| B3 | `vita/physics/CMakeLists.txt`, `shim/sp_timer_stub.cpp` | the **Mac** library (dylib and static archive) leaves out `Common/b2Timer.cpp` and links `shim/sp_timer_stub.cpp`, whose bodies are `b2Timer.cpp`'s own last (`#else`) branch -- the one the Vita build already compiles (it is neither `_WIN32` nor `__linux__`/`__APPLE__`): an empty constructor and `Reset`, `GetMilliseconds` returning 0. The Vita library is unchanged | plan v2 section 1.2 item 5 (new in v2.1; PhysBench finding 1): on the Mac, `b2World::Step` and `b2Island::Solve` call gettimeofday for b2Profile 4 times per island per step, 1.0-1.5 us per intro-sized step (6-16 %), so every Mac timing overstated the solver and the Mac and Vita builds differed here. With B3 b2Profile reads 0 on both. Proof (2026-10-14): T1 8/8 unchanged on the Mac (the timers feed no arithmetic); the dylib's link map has all four b2Timer symbols from `sp_timer_stub.cpp.o` and no `b2Timer.cpp.o` (`build.sh mac` checks it: `out/b3-linkmap.txt`; ld64 deduplicates the identical empty bodies, which its map then names "linker synthesized") | `-DSHEPPHYS_PROF=ON` (`build.sh prof` -> `build/mac-prof/`): the stock timer, for b2Profile phase splits; `physbench_mac_prof` links that library |

Other build flags (`-ffp-contract=off`, `-fno-exceptions`, `-fno-rtti`, `-fno-strict-aliasing`, `NDEBUG`) change no Box2D
arithmetic: Box2D uses neither exceptions nor RTTI, and `-ffp-contract=off` only forbids the compiler from fusing a*b+c.
`atan2f` and `expf` (referenced only by `b2Rope`) still come from libm; nothing the shim exposes calls them.
